# Notes for Claude

Burkay is learning blackjack (basic strategy → Hi-Lo counting → table play). He writes in Turkish and prefers short, direct answers. The apps' UI text is English except the two drills (strategy test, Hi-Lo trainer), which are Turkish.

## Layout

- `apps/<name>/index.html` — one self-contained file per app: markup, CSS and JS inline, no build, no dependencies except Google Fonts.
- `tests/` — jsdom simulations (`npm test`), Chrome screenshots (`npm run screens`).

- Every app ends its CSS with phone blocks: portrait `max-width:600px` and landscape `orientation:landscape and max-height:520px`, plus safe-area padding and home-screen meta tags. Keyboard-only text is marked `.kh` (inline) or `.kb` (hint line) and `kbd`; all hidden on `pointer:coarse`.

Keep each app a single file. After changing an app, run `npm test` (or `npm run test:quick`) and look at screenshots for layout changes.

## Publishing as Claude artifacts

- Slugs, URLs and the `db`/`user` declaration live in `CLAUDE.local.md` (gitignored). Never commit artifact URLs or slugs: the repo is public.
- Links between apps are relative (`../<app>/index.html`) so they work on GitHub Pages and from disk.

## GitHub Pages

- Repo is public; Pages deploys `main` / root automatically on every push.
- Apps: `https://burkay.github.io/blackjack-trainer/apps/<name>/`. No `window.claude` there, so progress stays in localStorage only (the code already guards for it).
- Commits use the GitHub noreply email; GitHub blocks pushes that expose the real one.

## Game data in Supabase

- Each app has a `CLOUD` module at the top of its script: anonymous Supabase sign-in (shared by all four apps through localStorage `bj-cloud-v1`), events queued in `bj-cloud-q-<app>` and posted in batches to `events`. Failures are silent; logging is off on `file://`, localhost and wherever `fetch` is missing (so jsdom tests and screenshots never send anything).
- Only game data: hands, exams, count checks, drill answers. Burkay chose explicitly: the apps send no visitor data (IP, location, device), no nickname, no cross-device sync. Supabase Auth itself still stores the IP and user agent of each sign-in (`auth.sessions`), so do not claim that nothing of the kind is kept.
- Schema and Row Level Security: `supabase/schema.sql` (run by hand in the SQL Editor). Players can read/write only their own rows; the dashboard sees all.
- The client key in the apps is the publishable key (public by design). Never put the secret/service_role key in the repo.
- `tests/cloud.test.js` checks the flow against a fake server.

## Table Simulator internals worth knowing

- Structure (one file, top to bottom): `/*LOGIC*/` chart, `/*SIDE*/` side bets + `RTP`, `/*EV*/` expected values, `/*ENGINE*/ … /*ENDENGINE*/` the game engine (no DOM), saved state + sync, `SND`, then the table: `G`, the views and `Game`. Tests slice the four marked blocks out of the source and patch `const G={`, `const SND={`, `const Dock={`: keep those strings.
- Engine classes: `Card`/`Shoe` (cut card, Hi-Lo `rc`, `tc`, `decksLeft`; `draw(up)` deals a copy with `uid` and its shoe index `at`, `reveal(c)` counts a face-down card when it turns), `Hand`, `Seat` (hands, `ins`, `spot`; bots have a betting strategy `FlatBet`/`ReverseMartingale` and a playing strategy `ChartPlayer`), `Dealer` (`hits(s17)`, `needs()`: nothing / second card only / play out), `Rules` (`Rules.from(S)`; `pA`/`p10`/`hole`/`spl`, `checks(up)`, `key` for `RTP`), `Bankroll` (`take`/`give`/`topUp` on `S.bank`), `Stats` (`hand()`, `bot()`, `streak()`, `game(k)` RTP, `house()`, `expLoss()`), and `Round`.
- `Round` is the round as a state machine: `run()` is a generator (deal → side bets → insurance → dealer's check → players → dealer → `settle()`) that yields an event at every step (`card`, `dealt`, `ask`, `insured`, `peek`, `reveal`, `nobj`, `decide`, `hit`, `double`, `split`, `sur`, `bust`, `done`, `dealer`, `draw`, `squeeze`, `dealerDone`) and takes the answers (your play, `'I'`/`'N'`, face down or not). `Game.show()` animates each event; `Round.replay()` runs the same generator with the chart. Change game rules only in `Round`: the table and the replay then cannot drift apart (`rule-replay.test.js` still checks that replaying your own move reproduces your result).
- UI objects: `Cards` (faces, card elements, `shown()`), `Chips`, `TableView` (felt, seats, banners, shuffle, suspense turn), `Dock` (action panel, next-hand buttons), `Bets` (drag and drop), `Coach`, `Pop` (bet check, top-up), `StatsView` (top bar, Stats tab, rule-breaking texts), `HistoryView`, `Layout`, `Menu`; `render()` redraws everything. `Game` is the controller: betting, `playRound()`, `show()`, `settle()`, your plays (`onAction`/`onIns`), records, exam, keyboard.
- Storage key `bj-masa-v1`. `S` is saved state. `G` is the table's in-memory state between engine and screen (phase on screen, your bets, `G.R` the round in play, `G.exam`, `G.busy`); `G.shoe/pos/cut/rc` read through to `SHOE` (tests stack the shoe through `G.shoe`), `G.turn` to `G.R.turn`. `BANK` and `STATS` work on `S`.
- `S.bots` is the **number** of other players (0–2). Their stats live in `S.botst` (`{0:{net,hands}, 2:{net,hands,bet,run}}`); seat 2 is "Player 1" (`ReverseMartingale`), seat 0 is "Player 2" (`FlatBet` €10). Play order is seat 2 → you (seat 1) → seat 0.
- Rules come as presets (`PRESETS`, menu "Rules"): **Hidden blackjack** (Burkay's own rules and the default for new tables since 2026-11-26: 8 decks, hole card checked under an ace only, so under a ten everyone plays and a blackjack shows at the end; split once, no surrender), **Online live** (8 decks, no hole card: second dealer card after the players, split once, no surrender), **US casino** (6 decks, hole card, dealer checks under ace and ten, split to 4, late surrender; same chart as the drills; it was the default for two days, `S.hrv` moves those tables to Hidden blackjack once), and **Custom** (anything else; `presetOf()`). Settings: `S.peek` ('both' | 'ace' | 'none'), `S.splits` (2 | 4), `S.decks`, `S.s17`, `S.sur`. A round uses the rules taken at its deal (`Rules.from(S)` into `G.R.rules`, soft 17 and surrender included), so menu changes wait for the next hand.
- Burkay's own table (2026-11-22) is Custom: hole card dealt face down (he disliked the second card coming later), checked under an ace only, split once, no surrender, 8 decks. Tables saved before the presets were mapped to exactly that. A blackjack the dealer did not check for takes **every** bet (his choice).
- The dealer's check for blackjack: "NO BLACKJACK" shows only after an ace (it answers the insurance question); under a ten the check is silent (Burkay asked for both).
- While a card is face down, the dealer's total shows the face-up cards (the up card alone while the hole card is down; 5+8 = 13 while a third card is being turned).
- `Dealer.needs()` says what the dealer still draws after the players (nothing / second card only / play out); with a hole card the card is already there.
- `decide()` gets `np10` / `npA` (no check under a ten / an ace) from the rules: against such a card 11 hits (vs 10 it doubles from TC +3), 10 never doubles, 8,8 is not split, and vs an ace A,A is not split. All computed by expected value; with both checked it is the standard chart. Fast Blackjack peeks, so it has none of this; the strategy test and Hi-Lo trainer teach the standard chart.
- Strategy: `decide()` between `/*LOGIC*/` and `/*END*/`; S17 tweaks and the Illustrious 18 + Fab 4 deviations live there. Fast Blackjack has its own copy; `tests/strategy-parity.test.js` keeps them in sync.
- "You vs the rule": `Round.snapshot(hi)` at your first off-chart move (`Game.onAction`), `Round.replay(snap, play, dev)` plays the same round on from there in real card order (other players and the dealer too, from a fixed copy of the shoe; `null` if it would run out), `Game.cfRecord()` keeps both results. Cards still in the shoe are marked `*` by their `at`. Burkay chose real card order explicitly — do not switch to a fixed dealer hand.
- Bets are placed by drag and drop (Burkay's wish: not by tapping): pointer events in `Bets.bind()`, chips onto a spot or its box, off a spot to take back, spot to spot to move. A tap only shows a hint; a keyboard click (no pointer before it, also `el.click()` in tests) adds to the box chosen last (`G.bt`). Refused chips always say why (`Bets.refused()`). Clear takes off all three bets.
- Top-up (Burkay's wish): whenever the bankroll falls below the table minimum (after a bet, insurance, double, split or at the end of a hand), `Bankroll.topUp()` adds €1,000 at once and `Pop.topUp()` shows a pop-up. It is play money, not a result: profit, RTP and house figures ignore it; `S.tu` counts top-ups (shown in Stats). The replay has its own `Bankroll` with the same rule.
- Unfinished hands: `Game.openHand()` saves the open hand in `S.pend` from the deal on, `Game.closePend()` books it on the next start: the bet is lost (Burkay chose this over a refund; closing the page must never undo a hand). Call `Game.openHand()` after any new money on the table.
- Side bets: `SIDE` between `/*SIDE*/` and `/*ENDSIDE*/`, bets in `G.sb`/`G.lastSb`, settled by `Round.sides()` right after the deal, results in `G.sbR`, saved as `rec.s` in the history; option `S.sbo`. They are separate from the hand result (streak, rule replay) but count in the bankroll, session/overall profit and exam net.
- RTP: `RTP` holds the game figures as percent of all money bet (main game simulated with 800M hands for each of the 48 rule combinations (decks × soft 17 × surrender × dealer check × splits) with this chart, side bets exact); rerun the simulation if the rules or the chart change. Your own figures are `S.rt` (`[bet, paid back]` for `m`, `pp`, `t3`), the other players' `S.botst[i].b/.w`, the house's `S.hs` (all bets at the table, same shape as `S.rt`; resets do not touch it; `S.hs0` is what the other players had lost before it existed). Purpose, in Burkay's words: what the real profit and loss of everybody, the house included, would have been. Small RTP text sits in `.rtx` next to the streak, each side bet's RTP above its circle (`.srt`), side bets together under "Your RTP" (`#s-rtps`), the house in `#house` on the chip rack.
- Wins in a row: `S.str` (you) and `S.botst[i].str`, shown in `.stk` under the name (flame from 2; a push keeps it). Profit: `S.ses` (session, ends after 30 min without a hand) and `S.tot` (overall, seeded from `S.hlog`); both are sums of hand results, so a bankroll reset does not touch them.
- Totals on the felt show the number only (A,A is 12, A,6 is 17): Burkay does not want "soft" written there. `handName()` keeps "soft" for the coach, the question line and the history, where it is said in words.
- End of a hand: the next-hand buttons (or the new-shoe offer) come first in `#act`, the result and the rule-breaking table below them, so continuing never needs a scroll. The three choices (Burkay's names): Continue with same bet (`Game.nextSame()`), Change Bet (betting screen), Change Shoe (shuffle, then deal with the same bet and side bets). The new-shoe offer after a bad run is only a note under them, with Change Shoe highlighted.
- Your blackjack gets its banner and tone only in `Game.settle()`, once it is paid: never at the deal, the dealer may have one too (Burkay's wish). Side-bet wins are paid at once, so they may celebrate right away.
- Suspense (`S.drama`, menu checkbox, on by default): when the dealer has a hard 14, 15 or 16 (Burkay's choice) and your hand is still live (`Round.tense`), the round's `draw` event is answered "face down" and `TableView.squeeze()` deals it face down, dims the table around the dealer (`.dim`), plays `SND.fx.tension` and turns the card slowly (`.peel`). Skipped with reduced motion; shorter at Fast speed (it goes through `T()`).
- Card sounds (`SND.fx.deal/flip/sweep/shuffle`) are timed to the animations: callers pass the delay `t`, the flight `fly`, the sweep `d` and the shuffle `dur`. Each card varies a little on purpose. Compare by rendering the sounds to WAV in an OfflineAudioContext (`SND.attach(ctx)`).
- Totals on the felt (yours and the dealer's) count only cards that show their face (`Cards.shown()`): never while a card flies face down or is turned slowly; the flight's end re-renders.
- Expected cost of a move off the chart: `evPlays()`/`evCost()` between `/*EV*/` and `/*ENDEV*/` (many-deck model, count tilt only with deviations on, hidden blackjack risk where the dealer does not check, split once + DAS). Shown in the coach's stop message, in the hand's rule-breaking note, in the history (`rec.e`, and per decision as the 5th field of `rec.x`) and in Stats (`S.cf.ev/evn/evr`: expected vs actual over the same hands).
- Hand history: `S.hlog`, newest first, capped at 1000. Rule-breaking totals: `S.cf`. Per-hand text: `StatsView.cfText()`.
- Deck colour alternates blue/red on every `Game.newShoe()` (`G.deckCol`, `:root[data-deck]`).
- Desktop: the table width follows the screen height (`--tmax`, leaving ~380px for the bar and the controls), so the bet panel and the next-hand buttons are on screen without scrolling down to 1280×720; the top bar and the dock keep at least 1240px (`max(var(--tmax),1240px)`).
- Phone layout lives at the end of the CSS. Portrait (`max-width:600px`): bankroll bar, table (`--R`, what is left of `--vh` after the bar, coach and controls), one-line coach strip `#coachP` (tap to expand; messages with buttons never collapse), one slim row of five actions. Burkay wants big cards, small buttons, and the stats out of the way: `Layout.place()` moves the stat boxes and the mode switch into `#mstat` under the controls (scroll to see them).
- `Layout.vh()` sets `--vh` from `innerHeight` only at the top of the page: Safari's bars make `svh` about 130px too small, and `dvh` would resize the table while scrolling.
- Landscape (`orientation:landscape and max-height:520px`): table left, dock right, dock scrolls. Safe areas via `env(safe-area-inset-*)`; keyboard hints use `.kh`/`kbd`, hidden on `pointer:coarse`.
- Check phone sizes with puppeteer at 440×862 and 440×728 (Pro Max, Safari bars hidden / shown), 390×664, 375×553, 932×380 and 844×330 landscape.
- Card faces and the card back are drawn in SVG here (classic casino look). Do not copy real brand designs (Bicycle Rider Back, Bee, etc.).
